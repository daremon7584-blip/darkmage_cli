# Сравнение: Gameforge CLI vs Claude Code по функционалу

Источник правды по Gameforge AI: `/root/saas-backend/API.md`, `app/schemas.py`, `GAMEFORGE_AI_ROADMAP.md`.
Claude Code — веб/десктоп CLI от Anthropic с интерактивным TUI, встроенным агентом и aprobацией действий.

## 1. Аутентификация и пользователь

| Возможность | Gameforge CLI | Claude Code |
|---|---|---|
| Регистрация аккаунта | `auth register` (email, пароль, имя) | Встроен в веб/CLI, OAuth + почта |
| Вход / токен Bearer | `auth login`, сохраняет токен в `~/.gameforge-cli/config.json` | Автоматический вход через профиль Anthropic |
| Текущий пользователь | `me` | Профиль в интерфейсе |
| Использование / лимиты | `usage` (5ч / неделя / месяц в процентах) | Лимиты по модели в интерфейсе |
| Память «Обо мне» | `memory get|put` (до 4000 символов) | «About me» / системные инструкции |
| Выход | `auth logout` | Выход из профиля |

## 2. Рабочие пространства (workspaces / проекты)

| Возможность | Gameforge CLI | Claude Code |
|---|---|---|
| Создание workspace | `workspace create --name` | Проект привязан к локальной папке / репозиторию |
| Список workspace | `workspace list` | Список недавних проектов |
| Информация о workspace | `workspace get` | Боковая панель проекта |
| Переименование / режим aprobации | `workspace update --name --approval-mode` | Настройки проекта |
| Запуск / остановка контейнера | `workspace start|stop` | Локальная папка, всегда доступна |
| Удаление | `workspace delete` | Удаление проекта из интерфейса |
| Изолированный sandbox (Docker + gVisor) | Да, через runner-manager | Локальная файловая система (опционально Docker) |
| Сетевая изоляция через прокси | Да (еgress proxy, только 80/443) | Полный локальный интернет |

## 3. Файлы

| Возможность | Gameforge CLI | Claude Code |
|---|---|---|
| Список директории | `files list <id> [path]` | Файловое дерево в интерфейсе |
| Чтение файла (с пагинацией offset/limit) | `files read <id> <path>` | Открытие файла в редакторе |
| Поиск по файлам (литеральный, регистрозависимый) | `files search <id> <query>` | Поиск по проекту (grep) |
| Редактирование файла (write/edit с aprobацией) | Нет в CLI (требуется через run/инструменты агента) | Прямое редактирование, inline-правки |
| Экспорт workspace как tar.gz | Только через API (`/export`) | Скачивание проекта / zip |
| Отказ от следования symlink | Да (серверная политика) | Локальные symlink работают как обычно |

## 4. Сессии и задачи (runs / задачи агента)

| Возможность | Gameforge CLI | Claude Code |
|---|---|---|
| Создание сессии | `session create <workspace_id> [--title]` | Сессия = чат, создаётся автоматически |
| Список сессий workspace | `session list <id>` | История чатов слева |
| Создание задачи (run) | `run create <session_id> --prompt ...` | Сообщение в ком포узере |
| План primero (plan_only) | `--plan-only` | Режим «Планирование» / мышление |
| Тщательный режим (thorough) | `--thorough` (кредиты) | Нет прямого аналога |
| Выбор модели | `--model` | Селектор модели (Haiku, Sonnet, Opus) |
| Получение статуса задачи | `run get <id>` | Статус в ленте задач |
| Остановка задачи | `run stop <id>` | Отмена генерации |
| Поток событий (SSE) | `run events <id>` | Живая лента шагов в реальном времени |
| Сообщения в ход задачи | Нет в CLI (`/runs/{id}/messages` есть в API) | Дополнение к задаче по ходу |
| Вопросы владельцу (ask_user) | Нет в CLI | Агент может задавать уточняющие вопросы |
| Откат задачи (revert) | Нет в CLI (API есть) | Откат изменений задачи |
| Ревью диффа по кнопке | Нет в CLI (API есть) | Проверка изменений |
| Одновременная задача на workspace | 1 активная задача | Одна активная генерация на чат |

## 9. Уникальные возможности Gameforge (не в Claude Code)

- Изолированные Docker+sandbox workspace с gVisor и own egress proxy.
- Строгая серверная политика одобрения (approval_policy), модель не может расширить права.
- Чекпоинты и откат состояния диска workspace до начала задачи.
- Детальный учёт стоимости каждого вызова модели (ai_usage, окна 5ч/неделя/месяц).
- Тарифы: бесплатный + Стандарт 990 ₽, кредиты, ручные платежи.
- Память проекта и «Обо мне» с подтверждением фактов через `remember`.
- Фоновые процессы в отдельном контейнере с границами sandbox.
- Сборка APK и экспорт Godot из задач.

## 10. Уникальные возможности Claude Code (не в Gameforge CLI)

- Интерактивный TUI-интерфейс (компоузер, лента шагов, правая панель диффов).
- Прямое редактирование файлов без создания «задачи».
- Встроенный терминал с shell и интерактивным вводом.
- Git-операции (коммит, push, PR, ветки) из интерфейса.
- MCP / расширения и подключение внешних инструментов.
- Саб-агенты и параллельные задачи.
- Суммирование контекста и компактировка истории автоматически.
- Поддержка локальных файлов без контейнеризации.

## 11. Сложность внедрения отсутствующих функций в Gameforge

Оценка сложности для команды, поддерживающей `/root/saas-backend` (FastAPI + SQLAlchemy/Alembic + Docker runner-manager + gVisor + approval_policy). Шкала: **Low** (дни), **Medium** (недели), **High** (месяцы).

| # | Возможность (от Claude Code) | Где сейчас | Сложность | Обоснование |
|---|---|---|---|---|
| 1 | Прямое редактирование файлов CLI без задачи | API есть (`/files/content`, `edit_file`), CLI нет | **Low** | Обёртка над существующими эндпоинтами, добавить флаг `--approve` или reliance на `approval_mode: auto`. |
| 2 | Сообщения в ход задачи (`/runs/{id}/messages`) | API есть, CLI нет | **Low** | Параметры запроса уже определены в `schemas.RunMessage`, нужно только CLI-команда + чтение из stdin. |
| 3 | Откат задачи (revert) | API есть (`POST /runs/{id}/revert`), CLI нет | **Low** | Прямая обёртка над эндпоинтом, проверка терминального статуса на стороне клиента. |
| 4 | Ревью диффа по кнопке | API есть (`POST /runs/{id}/review`), CLI нет | **Low** | Обёртка над эндпоинтом, вывод `findings`. |
| 5 | Фоновые процессы CLI | API есть (`start_process/.../stop_process`), CLI нет | **Low-Medium** | Нужны команды `process start|output|stop`, опрос вывода, привязка к workspace. |
| 6 | Картинки в задаче | API есть (`TaskImage`, до 3 шт.), CLI нет | **Low-Medium** | Чтение локального файла, base64, валидация сигнатур — уже в `schemas.py`. |
| 7 | Вопросы владельцу (ask_user) | Упомянуто вroadmap, API частично | **Medium** | Нужны интерактивные промпты во время SSE-потока, корреляция вопроса с ответом, таймаут 4 мин, лимит 3 раза. |
| 8 | Суммирование контекста / компактировка | Есть в воркере (`context.compacted`), без управления CLI | **Medium** | Настройка лимитов, отображение статуса компактировки, перенос саммари в следующие запуски. |
| 9 | Встроенный терминал с shell (интерактивный ввод) | Команды — одноразовые argv через API | **High** | Нужен persistent PTY-сеанс к sandbox-контейнеру, потоковый вывод, обработка сигналов (Ctrl+C), размер терминала, сетевая изоляция gVisor усложняет проброс. |
| 10 | Git-операции (коммит, push, PR, ветки) | Нет GitHub App, нет git-клиента в sandbox по умолчанию | **High** | Интеграция GitHub App, хранение OAuth-токенов, выполнение git в изолированном контейнере, работа с приватными репозиториями и PR API. |
| 11 | MCP / подключение внешних инструментов | Нет | **High** | Реализация MCP-сервера на стороне Gameforge, реестр инструментов, аутентификация клиентов, проксирование вызовов через approval_policy. |
| 12 | Саб-агенты и параллельные задачи | Один активный run на workspace | **High** | Изменение воркера и planner, распределение ресурсов sandbox, изоляция параллельных записей, конфликты чекпоинтов. |
| 13 | Полноценный TUI (компоузер, лента шагов, правая панель) | Чистый CLI, нет TUI | **High** | Переписка интерфейса на Textual/ Rich, 반응чивый ввод, отображение SSE-событий как ленты, интеграция с одобрением действий в реальном времени. |

### Сводка по сложности

- **Low (дни):** прямая правка файлов, сообщения в ход, откат задачи, ревью диффа.
- **Low-Medium (неделя):** фоновые процессы, картинки в задаче.
- **Medium (недели):** вопросы владельцу, управление контекстом/компактировка.
- **High (месяцы):** интерактивный терминал, Git-операции, MCP, саб-агенты/параллелизм, TUI.

Факторы, увеличивающие сложность в Gameforge по сравнению с Claude Code:
1. **Разделение ролей:** API, worker и runner-manager — разные сервисы, изменения требуют согласованного выката нескольких контейнеров (см. `docker-compose.yml`).
2. **Безопасность:** Docker-сокет только у `runner-manager`; любая интерактивная работа с контейнером требует проксирования через runner, а не прямого доступа.
3. **gVisor:** ограничения на файловые операции и сеть в sandbox усложняют проброс терминала и импорт репозиториев.
4. **Политика одобрения:** любое изменение файла или команда проходит через `approval_policy.py`; TUI и интерактивный терминал должны уважать durable owner approval.
5. **Чекпоинты/откат:** параллельные записи и интерактивные правки ломают assumptions о едином активном мутирующем run на workspace.

## Итог

Gameforge CLI покрывает базовые сценарии работы с платформой: авторизация, workspace, файлы, сессии, запуск задач агента и поток событий, прямой чат. Он не заменяет Claude Code в части интерактивного редактирования кода, встроенного терминала, Git-интеграции и TUI. CLI подходит для скриптовой автоматизации и управления удалёнными sandbox-пространствами, а Claude Code — для интерактивной разработки на локальном репозитории.

Быстрые победы для Gameforge CLI (до 1 недели): команды правки файлов, сообщения в ход задачи, откат, ревью диффа, фоновые процессы, картинки. Среднесрочно (1–4 недели): интерактивные вопросы владельцу, управление контекстом. Долгосрочно (1–3 месяца каждая): интерактивный терминал, Git-операции, MCP, саб-агенты, полноценный TUI.
