## 4. Детальные требования к каждой функции

### 4.1 Прямое редактирование файлов (`files edit|write|delete` без run)

**Текущее состояние:** Редактирование файлов возможно только через создание run с `edit_file` инструментом, который требует одобрения владельца.

**Требуется:**
- Команда `odyssey files edit <workspace_id> <path> --content "..."` без создания run
- Поддержка `base_content` для проверки конфликтов (как в `edit_file` инструменте)
- Поддержка stdin (`--content -`)
- Валидация пути файла, размера (256 KiB лимит)
- Интеграция с approval policy (запрос подтверждения в `ask` режиме)

### 4.2 Прямое создание и удаление файлов (`files write|delete`)

| Возможность | Описание | Критичность |
|-------------|----------|-------------|
| `files write <workspace_id> <path> --content "..."` | Создание файла без создания run | Высокий |
| `files delete <workspace_id> <path>` | Удаление файла без создания run | Высокий |
| Поддержка `base_content` для проверки конфликтов | Проверка что файл не изменился с момента чтения | Средний |
| Поддержка `session_id` | Привязка операции к сессии для контекста | Средний |

### 4.3 Улучшенный вывод `run events`

| Функция | Описание | Критичность |
|---------|----------|-------------|
| **Цветной вывод по типам событий** | `run.started` (синий), `assistant.delta` (зелёный), `tool.requested` (синий), `approval.required` (жёлтый), `run.completed` (зелёный bold), `run.failed` (красный) | Высокий |
| **Фильтрация по типам событий** | `--event-type run.started,assistant.delta,tool.*` | Средний |
| **Автоподключение при запуске задачи** | Автоматически подключаться к событиям при создании run | Средний |
| **Отображение времени и длительности** | Время начала, окончания, длительность каждого события | Средний |
| **Автоподключение при запуске задачи** | Автоматически подключаться к событиям при создании run через `run create` | Средний |

### 4.4 История команд (`odyssey history [N]`)

| Возможность | Описание | Критичность |
|-------------|----------|-------------|
| **Хранение в `~/.odyssey-cli/history.json`** | Все выполненные команды с временными метками | Высокий |
| **Повтор команды по номеру** | `odyssey history 3` — повторить 3-ю команду из истории | Высокий |
| **Отображение последних N команд** | `odyssey history` показывает последние 10 команд по умолчанию | Средний |
| **Поиск в истории** | Поиск по командам через подстроку | Низкий |
| **Экспорт/импорт истории** | Экспорт в JSON/JSONL для переноса на другой компьютер | Низкий |

### 4.5 Автодополнение (shell completion)

| Оболочка | Команда установки | Место хранения |

## 14. Приоритеты реализации

### Высокий приоритет (сделать в первую очередь):

1. **Прямое редактирование файлов (`files edit` без создания run)** — это 가장 часто запрашиваемая функция, которая значительно ускоряет работу с файлами
2. **Загрузка/скачивание файлов** — необходимо для работы с внешними файлами и экспортом результатов
3. **Дерево файлов (`files tree`)** — наглядное представление структуры проекта
4. **История команд (`history [N]`)** — удобство повторения команд
5. **Автодополнение (shell completion)** — ускоряет работу опытных пользователей

### Средний приоритет (1-2 недели):

1. **Улучшенный `run events`** — цветной вывод, фильтрация по типам событий
2. **Улучшенный `workspace list`** — цветной вывод, статус, размер
3. **Автоподключение к `run events` при создании задачи** — удобство использования
4. **Улучшенный `workspace list`** — цветной вывод, статус, размер

### Долгосрочно (1-3 месяца):

1. **Полноценный интерактивный терминал (`odyssey term`)** — PTY с поддержкой размеров экрана, цветом, историей команд
2. **Интеграция Git в TUI** — `odyssey git clone|commit|push|pr` внутри TUI
3. **Полноценный TUI (`odyssey tui <workspace_id>`)** — разделённая на панели (разговор, файлы, терминал, diff)
4. **Саб-агенты (параллельные задачи)** — возможность запуска нескольких task runs в одном workspace с изоляцией чекпоинтов
5. **Публичный API** — документация для внешних интеграций

## 15. Заключение

Odyssey CLI представляет собой хорошо спроектированный инструмент для работы с AI-агентами в изолированных sandbox-пространствах. Основные сильные стороны:

1. **Изолированный sandbox (Docker+gVisor)** — уникальное преимущество перед Claude Code, Codex и другими CLI-агентами
2. **Серверная политика одобрения** — модель не может расширить права без владельца
3. **Чекпоинты и откат** — возможность вернуть состояние workspace до задачи
4. **Детальный учёт стоимости** — каждый вызов модели учтён с привязкой к окнам 5ч/неделя/месяц
5. **Тарифная система** — бесплатный + платный (990 ₽/мес) + кредиты
6. **Полный REST API** — любая интеграция возможна

Основные направления развития:

1. **Быстрые победы (1-2 недели):** прямая правка файлов, загрузка/скачивание, дерево файлов, история команд, автодополнение, улучшенный вывод событий
2. **Среднесрочно (1-3 недели):** полноценный интерактивный терминал PTY, Git-операции в CLI, улучшенный вывод событий
3. **Долгосрочно (1-3 месяца):** полноценный TUI, Git-операции в TUI, саб-агенты, параллельные задачи

Этот дорожная карта обеспечит Odyssey CLI конкурентные преимущества перед Claude Code, Codex и другими AI-агентами, сохраняя при этом уникальные преимущества изолированного sandbox и серверной политики одобрения.
