## 1. Общее описание проекта

**Odyssey AI** — это платформа для разработки с помощью AI-агента, которая позволяет пользователям создавать изолированные рабочие пространства (workspaces), в которых выполняются задачи с помощью языковой модели (LLM) через OpenRouter. Основная цель — предоставить безопасную среду для выполнения кода AI-агентом с детальным контролем владельца, учётом стоимости и возможностью отката изменений.

### Ключевые характеристики

| Параметр | Значение |
|----------|----------|
| Язык бэкенда | Python 3.10+ (FastAPI, SQLAlchemy, Alembic) |
| Язык фронтенда | React + TypeScript + Vite |
| База данных | PostgreSQL + Redis |
| Песочницы | Docker + gVisor (изолированные контейнеры) |
| ИИ-провайдер | OpenRouter (Claude Haiku 5.5, GLM-5.3-Flash, Nemotron и др.) |
| CLI клиент | Кастомный Python CLI (`/root/odyssey-cli/`) |
| Тесты | 46 тестов (backend API + пользовательские CLI тесты) |
| Статус | Живой сервер в Финляндии, браузерный e2e 7/8 проходит |
| Дата дорожной карты | 29.10.2026 |

## 3. Ключевые принципы и инварианты

Проект определяет строгие инварианты в `AGENTS.md`, которые должны соблюдаться при любой разработке:

1. **Владение workspace выводится от аутентифицированного пользователя.** Никогда не доверять клиент-supplied `owner_id`.
2. **Docker socket принадлежит только runner-manager.** API, worker и sandbox контейнеры не должны получать его.
3. **Файловые операции workspace** остаются внутри workspace root и отвергают traversal и следование symlink.
4. **Workspace write и команды проходят через approval_policy.py** —耐久 owner approval, или в auto mode allowlisted acción после чекпоинта. Только серверная политика решает.
5. **Проверить чекпоинт и rollback семантику** при изменении writes, commands или workspace storage.
6. **Изменение схемы БД через Alembic миграции** — поддерживать пустую и существующую базу.
7. **Хранить .env, credentials, test-user data, generated artifacts вне коммитов.** `.env.example` содержит только шаблоны.

## 4. Детальный анализ по областям

### 4.1 Аутентификация и пользователи

**Реализация:** `app/endpoints/auth.py`, `app/models.py` (модель `User`)

**Возможности:**
- Регистрация (`POST /auth/register`) с email, паролем (8-128 символов), именем, принятием условий и персональных данных
- Вход (`POST /auth/login`) с JSON или form-urlencoded, HS256 JWT токены, время жизни настраивается (`ACCESS_TOKEN_EXPIRE_MINUTES`, default 720 мин)
- `GET /users/me` — текущий пользователь
- `GET/PUT /users/me/memory` — "About me" до 4000 символов
- `GET /users/me/usage` — окна использования (5ч, неделя, месяц) в процентах
- `GET /users/me/audit` — аудит событий (метаданные без промптов/путей)

**Проблемы и ограничения:**
- Нет refresh токенов — lifetime токена = время сессии (до 720 мин по умолчанию)
- Нет двухфакторной аутентификации (2FA)
- Нет подтверждения email при регистрации (планируется с доменом и почтой)
- Нет социальных входов (Google, GitHub и т.д.)

### 4.2 Workspaces (рабочие пространства)

**Реализация:** `app/endpoints/workspaces.py`, `app/models.py` (модель `Workspace`)

**Возможности:**
- Создание workspace с именем (1-120 символов)
- Статусы: `creating`, `starting`, `ready`, `stopped`, `error`
- Режимы одобрения: `auto` (авто после чекпоинта) или `ask` (каждая запись ждет одобрения)
- Разрешенные команды (`allowed_commands`) — до 20 команд с argv префиксами
- Проверка после правки (`post_edit_check`)
- Запуск/остановка sandbox контейнера (Docker + gVisor)
- Файловые операции: список, чтение (с пагинацией), поиск, экспорт (tar.gz)
- Сессии и память workspace

**Проблемы и ограничения:**
- Новый workspace создается пустым — импорт репозитория не подключен к этому эндпоинту (отдельный endpoint `/repository`)
- На бесплатном тарифе workspace стартует только для каждой задачи (shared sandbox)
- Лимит на количество одновременно запущенных workspace
- Нет встроенного импорта git архива из UI (только через API)

### 4.3 Runs (запуски агентов)

**Реализация:** `app/endpoints/runs.py`, `app/worker.py`

**Статусы:** `queued`, `running`, `waiting_approval`, `completed`, `failed`, `cancelled`  
**Состояние чекпоинта:** `none`, `available`, `reverted`, `expired`

**Возможности:**
- Создание run с промптом (до 16,000 символов), моделью, plan_only, thorough, изображениями (до 3)
- SSE поток событий с последовательностью (`run.started`, `assistant.delta`, `tool.requested`, `tool.started`, `tool.output`, `approval.required`, `approval.resolved`, `checkpoint.ready`, `checkpoint.resolved`, `diff.ready`, `run.completed`, `run.failed`, `run.cancelled`)
- Сообщения в ход задачи (`POST /runs/{id}/messages`)
- Ревью диффа (`POST /runs/{id}/review`)
- Откат задачи (`POST /runs/{run_id}/revert`)
- Ревью по кнопке
- Проверка после правки (post_edit_check)

**Ограничения:**
- Один активный run на workspace (за исключением plan_only runs)
- Один активный мутирующий run на workspace (конфликт чекпоинтов)
- Лимиты: AGENT_MAX_MODEL_CALLS (50), AGENT_MAX_TOOL_CALLS (100), AGENT_MAX_CONTEXT_TOKENS (96000), AGENT_MAX_RUN_SECONDS (900), AGENT_MAX_RUN_COST_USD ($0.50)
- Окна расходов пользователя: 5ч ($1.00), неделя ($2.50), месяц ($5.50)

### 4.4 Инструменты агента (runner/worker)

Из `app/worker.py` и `ODYSSEY_AI_ROADMAP.md`, агент имеет 18 инструментов:

| Инструмент | Описание |
|------------|----------|
| `read_file` | Чтение файла с пагинацией |
| `write_file` | Запись файла (требует одобрения) |
| `edit_file` | Замена текстового фрагмента (требует одобрения) |
| `run_command` | Выполнение команды (требует одобрения) |
| `start_process` | Фоновый процесс (до 2 на проект, до 30 мин) |
| `process_output` | Вывод фонового процесса |
| `stop_process` | Остановка фонового процесса |
| `ask_user` | Вопрос владельцу (1-4 вопроса, 4 мин на ответ, не более 3 раз за задачу) |
| `check_preview` | Проверка страницы (рендерер Chromium под gVisor) |
| `generate_image` | Генерация картинки (Nano Banana 2 Lite) |
| `build_apk` | Сборка APK |
| `export_godot` | Экспорт Godot игры |
| `web_fetch` | Веб-запрос (через прокси) |
| и др. |

**Проблемы:**
- Фоновые процессы ограничены 2 на проект и 30 минут
- Нет поддержки параллельных пишущих агентов (явно указано в решениях)
- Нет Explore-субагента для больших репозиториев

## 5. Безопасность

### Реализованные меры безопасности

| Мера | Реализация |
|------|------------|
| gVisor | Да, release-20261019.0, проверено |
| Изоляция сети песочницы | Полный интернет без внутренних адресов, через прокси (ports 80/443, 2 МБ/с) |
| gVisor symlink уязвимость | Исправлен (open_child_directory с lstat + проверка inode) |
| Docker socket | Только у runner-manager |
| R-02 | Токены ролей, аренды |
| R-03 | Квоты |
| Закрепленные образы | Зафиксированные образы, lock-файлы |
| Trivy в CI | Сканирование уязвимостей |
| Обновлённые зависимости | Да |
| RKN уведомления | Черновики, план уведомлений |
| 152-ФЗ документы | Подготовка к переезду в РФ |
| Удаление аккаунта | Есть |

### Известные проблемы безопасности
- gVisor открывает симлинк на папку при `O_DIRECTORY|O_NOFOLLOW` (исправлено, но требует пересборки образа)
- Нет 필тра «опасного контента» на запись и команды (осознанное решение)
- Нет сканера prompt injection при чтении (осознанное решение)

## 7. Сильные стороны Odyssey AI

1. **Изолированные sandbox-рабочие пространства** с gVisor и строгой политикой одобрения — уникальное преимущество для работы с недоверенным кодом

## 11. Выводы

Проект Odyssey AI находится в **активной стадии разработки** с живым сервером и работающим кодом. Основная сильная сторона — изолированные sandbox-пространства с серверной политикой одобрения, что делает платформу подходящей для работы с недоверенным кодом.

Критические блокеры для запуска бета — домен+HTTPS, переезд в РФ, автоматическая оплата, мониторинг и пополнение OpenRouter баланса. Эти вопросы должны быть решены в первую очередь.

Проект имеет хороший потенциал для ниши «безопасная разработка с AI-агентом», но требует значительных инвестиций в инфраструктуру (домен, HTTPS, мониторинг, оплату) перед запуском публичной бета.
